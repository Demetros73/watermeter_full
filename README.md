# WaterMeter — ESP32-C3 SuperMini

Проект учета холодной и горячей воды на чистом C11, PlatformIO + ESP-IDF 5.3.x.

## Состав

- Герконовые счетчики ХВС/ГВС на GPIO3/GPIO4, аппаратные прерывания и программный автомат антидребезга.
- Подсчет литров в `uint64_t`; импульсный вес задается отдельно для каждого счетчика.
- История расхода за 12 календарных месяцев, несинхронизированный расход до получения SNTP.
- NVS с версионированием и сравнением снимков; сохранение после 15 секунд тишины, без лишних записей.
- Wi-Fi STA/AP, повторное подключение с экспоненциальной задержкой 2–60 секунд.
- SNTP и настраиваемая TZ.
- MQTT retained публикация при изменении показаний и не реже раза в минуту.
- Telegram: тестовая отправка, регулярный интервал и ежемесячная отправка 21-го числа в установленное время.
- Локальный mobile-first веб-интерфейс, встроенный в прошивку без CDN.
- Переключение светлой и темной темы с сохранением выбора в браузере.

## Распиновка ESP32-C3 SuperMini

| Назначение | GPIO | Настройка |
|---|---:|---|
| Геркон ХВС | GPIO3 | Вход, подтяжка к 3.3 В, прерывание по спаду |
| Геркон ГВС | GPIO4 | Вход, подтяжка к 3.3 В, прерывание по спаду |
| Синий LED платы | GPIO8 | Выход, инверсная логика: 0 — светится |
| Кнопка BOOT | GPIO9 | Вход, активный низкий уровень, удержание 5 секунд |
| USB Serial/JTAG | GPIO18/GPIO19 | Не использовать для периферии |

GPIO2, GPIO8 и GPIO9 не назначаются входами счетчиков. GPIO8 и GPIO9 заняты штатными LED/BOOT. Для импульсных входов используется GPIO3/GPIO4.

### Подключение герконов

- Один контакт геркона — GPIO3 (ХВС) или GPIO4 (ГВС).
- Второй контакт — GND.
- Внутренняя подтяжка ESP32-C3 включена программно.
- Для длинных проводов рекомендуется внешняя подтяжка 4.7–10 кОм от входа к 3.3 В и керамический конденсатор 0.1 мкФ от входа к GND.
- Не подавать на GPIO напряжение выше 3.3 В.

Входной контакт замкнут на GND при активном магните/замыкании геркона. Импульс принимается, если спустя 80 мс вход всё еще LOW. Следующий импульс разрешается только после непрерывного HIGH в течение 100 мс.

## Сборка и прошивка

1. Установить Visual Studio Code и расширение PlatformIO IDE либо PlatformIO Core.
2. Распаковать архив в отдельную папку.
3. Открыть в VS Code именно папку, где лежит `platformio.ini`.
4. Дождаться установки платформы `espressif32@6.10.0` и фреймворка ESP-IDF.
5. Подключить ESP32-C3 SuperMini USB-кабелем с линиями данных.
6. В PlatformIO выбрать среду `esp32-c3-supermini`.
7. Выполнить **Build**, затем **Upload**.
8. Открыть Serial Monitor на 115200 бод.

Команды PlatformIO Core из терминала в каталоге проекта:

```bash
pio run
pio run -t upload
pio device monitor -b 115200
```

Если загрузка не начинается автоматически, удерживать BOOT, кратко нажать RESET (если он есть), затем отпустить BOOT после начала подключения загрузчика.

## Первый запуск и Wi-Fi

Если в NVS нет SSID, устройство создает точку доступа:

- SSID: `WaterMeter-Setup`
- Пароль: `12345678`
- Адрес интерфейса: `http://192.168.4.1`

В настройках введите домашний SSID и пароль, нажмите «Сохранить настройки». При изменении SSID устройство перезагрузится и перейдет в STA. Если домашняя сеть недоступна, устройство продолжает повторные подключения с backoff и не создает AP самопроизвольно.

Для возврата к режиму настройки удерживайте BOOT не менее 5 секунд. Будут очищены только SSID и пароль Wi-Fi; счетчики, история, MQTT и Telegram сохраняются.

## Настройки интеграций

### MQTT

Укажите хост брокера, порт, учетные данные и базовый топик. Публикуются retained-сообщения:

- `<base_topic>/cold` — текущее ХВС в м³;
- `<base_topic>/hot` — текущее ГВС в м³;
- `<base_topic>/state` — JSON с общими показаниями, расходом месяца, RSSI, контактами и состоянием времени.

Публикация выполняется при изменении общих показаний и периодически раз в минуту. Используется обычный `mqtt://` без TLS; для брокера в недоверенной сети используйте защищенный сегмент LAN/VPN.

### Telegram

Создайте бота через BotFather, укажите токен и Chat ID. Включите Telegram и нажмите «Отправить тест». HTTPS проверяется через встроенный набор корневых сертификатов ESP-IDF.

Регулярная отправка может быть отключена или настроена на 24 часа, 7 дней либо 30 дней. Независимо от нее можно включить ежемесячный отчет 21-го числа. После успешной отправки `last_monthly_ym` записывается в NVS, поэтому перезагрузка не вызывает повторную отправку за тот же месяц.

### Часовой пояс

Используется POSIX TZ. Примеры:

- Москва: `MSK-3`
- Центральная Европа: `CET-1CEST,M3.5.0,M10.5.0/3`

Для корректного календарного учета дождитесь синхронизации SNTP. До синхронизации общий объем счетчиков продолжает увеличиваться, а расход временно копится отдельно; после получения времени он переносится в текущий календарный месяц.

## API

| Метод | URI | Назначение |
|---|---|---|
| GET | `/` | Встроенный интерфейс |
| GET | `/api/status` | Текущие показания и состояния |
| GET | `/api/history` | 12 месяцев истории и итоги |
| GET | `/api/settings` | Настройки без секретных паролей и токена |
| POST | `/api/settings` | Сохранение настроек и ручная корректировка счетчиков |
| POST | `/api/telegram/test` | Тестовое сообщение Telegram |

Ручная корректировка передается в JSON полями `cold_m3` и/или `hot_m3`. Поля можно опустить, если соответствующий счетчик не корректируется. Изменение показаний сохраняется немедленно и не добавляется в месячный расход.

## Важные замечания

1. В проекте не реализована авторизация веб-интерфейса: в режиме AP пароль Wi-Fi защищает первичную настройку, но в домашней LAN любой клиент, имеющий доступ к IP устройства, сможет читать и изменять данные. Не публикуйте HTTP-порт устройства в Интернет.
2. MQTT использует незашифрованное соединение `mqtt://`; используйте брокер в доверенной сети.
3. В `platformio.ini` выбрана типовая цель `esp32-c3-devkitm-1`, совместимая с ESP32-C3 SuperMini по MCU. Разводка периферии задается GPIO в коде.
4. Реальное время расхода, контакты, Wi-Fi, NVS и интеграции необходимо проверить на конкретной ревизии платы и счетчиков перед постоянной эксплуатацией.
5. Для корректной сборки нужен PlatformIO с доступом к загрузке платформы и пакетов Espressif. В этой среде сборка ESP-IDF не запускалась, так как `pio`/`idf.py` не установлены; исходники подготовлены под ESP-IDF 5.3.x, но перед прошивкой следует выполнить Build и устранить возможные различия пакетов/ревизий.
